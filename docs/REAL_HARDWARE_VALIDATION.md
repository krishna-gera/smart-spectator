# Real Hardware Validation Report

## 1. Validation Methodology & Rules

In strict accordance with the non-fabrication rule, this report separates:
- **MEASURED**: Real benchmarks executed and timed on active host hardware.
- **EXPECTED**: Architectural performance targets for target deployment platforms (Snapdragon X Elite).
- **NOT AVAILABLE**: Capabilities that cannot run on the present hardware (e.g. QNN on macOS).
- **NOT TESTED**: Scenarios not physically tested in this session.

## 4. Hardware Fallback Verification

The inference provider fallback hierarchy was validated through `InferenceProviderManager`:
1. **Tier 1 (QNN)**: Correctly flagged as `NOT AVAILABLE` on the current host. No crashes or unhandled exceptions occurred.
2. **Tier 2 (DirectML / CoreML)**: Detected and selected as preferred provider on host. Both models executed cleanly.
3. **Tier 3 (CPU Fallback)**: Explicitly tested with `get_preferred_provider("cpu")` and verified functional.
